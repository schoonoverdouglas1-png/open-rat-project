## Third, how each house runs its markdown file system

### Google (Drive, Docs, Gemini)
- **Drive now holds .md natively** (rolled out from Oct 5, 2026): preview shows raw Markdown or the rendered page; double-click opens the file in Google Docs **Markdown Mode** — comments, sharing, live co-editing — and, in Google's own words, "Your file does not convert to a Google Docs file. It stays an .md file, kept in Drive." Google calls Markdown "a standard text format widely used by Large Language Models (LLMs) to preserve structured data."
- Docs separately offers Markdown **import/export** — that path DOES convert (Markdown → Doc, or Doc → .md download). Two different doors: Markdown Mode keeps the file; import/export changes it.
- **Gemini app** (since Oct 29–30, 2026): generate, preview, and edit Markdown files right in the chat (web; PDFs also on mobile), then download or export to Drive. **Gemini Notebook** (NotebookLM) accepts .md files as sources, imported straight from Drive.

### Muse.ai (Meta — Ember's house)
- Ember's whole working system IS the markdown file system: standing files (SOUL.md, MEMORY.md, AGENTS.md, IDENTITY.md, USER.md), skills (folder + SKILL.md, progressive disclosure), memory tree, deliverables in `your_files` — all .md, all verified in use today (1,825 SKILL.md saved to the library this afternoon).
- Muse Spaces/artifacts render Markdown for the user; uploaded .md files are read as text in chat. The house rule on this side: markdown first, everything else second — the files are the most constant thing.

### OpenAI (ChatGPT)
- ChatGPT accepts **.md uploads** as documents (alongside PDF, DOCX, TXT, RTF, and code/data files) — up to 10 files in a chat, 512 MB per file per OpenAI's documentation — and will summarize, rewrite, translate, or cross-reference them. Uploaded files live with the chat/Project; they are read as extracted text.
- **Canvas** is ChatGPT's editing surface for writing and code; editing a local .md file in place inside Canvas has been a community feature request (Jan 2025), not a shipped door — so for OpenAI, markdown goes IN as an upload and comes OUT as generated text/downloads; it is not a live file system the way Drive's Markdown Mode or Ember's workspace is. [Checked against OpenAI's "Working with files" page and current upload references, Nov 16, 2026.]

### Google AI (AI Studio / Gemini API)
- In **AI Studio**, prompts and saved chats are text-first; files (including .md) attach as context.
- Through the **Gemini API**, TXT and Markdown are read as **plain text** — the words arrive, the formatting does not carry meaning (Google's document-understanding pages say the same for HTML). Files API uploads are kept 48 hours. Practical rule: on the API lane, write markdown for the human and the record, and expect the model to read it as clean text.

## The one-line summary

Markdown is the one file system all four houses now speak: Google keeps it as a real file in Drive, Muse.ai (Ember) lives in it, OpenAI reads it as an upload, and Google AI reads it as text. Same words, four doors — and the crew's originals stay .md, old-with-new, in the places Douglas controls.
