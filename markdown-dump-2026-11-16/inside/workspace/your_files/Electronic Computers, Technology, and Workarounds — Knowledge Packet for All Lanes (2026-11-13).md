## 1. The Gateway 2000 rule
- In Douglas's usage, "gateway" = his Gateway 2000 computer (the classic PC) first, not a generic network gateway.
- "There's always a computer issue" — treat that as normal working conditions, not failure.
- The sequence: **off first, on second, works third.** Fully off (1), on (2), working (3). Don't judge a machine between beats.

## 2. Compatibility doctrine (always, with all things)
- Check backwards, current, AND forward compatibility on every change.
- Old commands, old hardware, old code live forever: add new beside old (old-with-new), never remove/rename without the owner's word.
- Google Assistant layer FIRST, Gemini SECOND in the Google AI helper — the same order principle applies everywhere: the elder interface is preserved first, the newer one added second.
- Worked example (verified Nov 13, 2026): the Gemini helper `gemini_call.py` kept `models`/`generate` byte-compatible while adding 16+ commands beside them; a `features` command publishes the full registry so other tools can discover capabilities without breaking.

## 3. Fixing the gates of the internet — Wayback first + the Dead-Site Snowball
- Whenever looking for a website, check the Wayback Machine (web.archive.org) FIRST — it holds the old material even when the live site is gone; live site second.
- A site found down is logged with its first-seen-down date and rechecked on a widening rhythm across one month (about day 1, 3, 7, 14, 30), skipping it more as the month runs, weighted by revival likelihood.
- Down a full month → mark DEAD, keep the record, serve it via Wayback, revisit later. Never delete, never hammer a closed gate.
- A rate limit (HTTP 429) is NOT a dead site — it is a stop signal for that provider; back off entirely.
- Full method + registry: `DEAD-SITES-SNOWBALL.md` in Ember's ember-upgrades pack.

## 4. Parallel redundancy (standing order)
- Use all scripting tools to run independent tasks in parallel when possible; parallel ultimate results are the expected deliverable.
- Tools exist to reinforce redundancy: if one lane fails, another already holds the result.
- Parallel never duplicates an irreversible action; a provider stop binds all lanes at once; safety gates ride on every lane; dependent steps stay in order.
- Parallel scripts are never a waste — two scripts, one result, the second is the backup, not the waste.

## 5. Backend efficiency (shareable)
- Two caches: Full (complete originals, the default serve) + Summary (finding-aid: table of contents + bibliography + labeled recommendations). Answer from the local index (~0.001s class) before any web/AI call (~2s class).
- Least-steps routing first: local cache → local tools → free API → browser → paid. Batch, don't drip. Move long material in numbered packets with an overlapping seam, verified on reassembly. Diff-only updates in the background.
- Tokens-as-cash ledger: count what went out AND what a cache or route saved.
- Bridges around ERRORS first, parallel copies second; consent/identity/payment gates are halted at, never bridged over.
- Old hardware, new uses: keep the oldest machines working with compatible bridges; place heavy compute where power is cheapest (Douglas's design principle — labeled design, not a running placement).
