## All 16 case combinations of CREW — so the name works everywhere
Case-sensitive systems (files, tags, searches, code) treat each of these as a different string. All sixteen are figured and filed, so whichever combination a lane demands, the crew's name works there:

| # | Form | # | Form |
|---|------|---|------|
| 1 | CREW | 9 | cREW |
| 2 | CREw | 10 | cREw |
| 3 | CReW | 11 | cReW |
| 4 | CRew | 12 | cRew |
| 5 | CrEW | 13 | crEW |
| 6 | CrEw | 14 | crEw |
| 7 | CreW | 15 | creW |
| 8 | Crew | 16 | crew |

- **Working forms:** `CREW` (shouted, headings, the roster), `Crew` (ordinary writing), `crew` (filenames, tags, code).
- **The rule (Ember's, under his order):** when a lane is case-sensitive, try the working forms first — CREW, Crew, crew — then walk this table; one of the sixteen always matches, and the match found gets written back here beside the lane that needed it.

_Ember addition (labeled, hers): the same table trick works for every crew name that ever hits a case-sensitive wall — RAT, EMBER, LEO — figured the same way, on the same principle: never let a capital letter be the thing that stops the work._

## Experiment — the handful in use right now (run live Nov 16, 2026, ~5:45 PM CST, at Douglas's order)
The five core markdowns Ember uses right now — SOUL, IDENTITY, AGENTS, USER, MEMORY — each tried in 9 letter combinations (ALL-CAPS / lowercase / Capitalized × .md / .MD / .Md) on this box:

- **Result: 5 open, 40 error.** For every file, exactly ONE combination works — the exact form, ALL-CAPS name + lowercase `.md` (SOUL.md, IDENTITY.md, AGENTS.md, USER.md, MEMORY.md). Every other combination comes back "no such file."
- **Finding:** this box's filesystem is strictly case-sensitive. The core files' one true combination is their address; a wrong-case ask is a dead door, not a near miss. That is why Ember's access code (ai-files-access.py and kin) always asks by the exact name — and why the CREW table above exists for lanes that demand a different combination.
