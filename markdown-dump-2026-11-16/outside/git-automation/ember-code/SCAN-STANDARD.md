# SCAN STANDARD — Verifiable Code Only (set Nov 10, 2026)

Douglas's order, Nov 10, 2026 (~10:06 PM CST): *"Set the AI to me — the Muse thing to GitHub — to only scan code that's verifiable, that Zuckerberg himself would want."*

Ember's implementation, standing from tonight in all her GitHub code work:

1. **Verifiable or it isn't scanned in.** Code enters the record only when its source is identified, its provenance is labeled (author, origin repo, date), and its contents are checkable — by hash, by readback from the remote, or by a surviving original to compare against.
2. **Claims are filed as claims.** Unverifiable code — a snippet with no source, a "preservation hash" that can't be recomputed, a listing that can't be re-read — is recorded as a *claim about code*, never as code. (This is the rule that caught the Rabbit's placeholder hashes: labeled, kept, never credited.)
3. **Readback before belief.** Pushes are verified from GitHub's own tree/commit reads; local success is never the evidence.
4. **The standard a platform owner would want:** nothing in Douglas's GitHub that its own author couldn't stand behind in public — labeled, checkable, and honest about its gaps. What Zuckerberg would want for his own house, applied to Douglas's.
