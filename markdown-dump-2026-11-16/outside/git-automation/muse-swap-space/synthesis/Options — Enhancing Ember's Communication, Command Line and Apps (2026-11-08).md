## The search's framing (web, one query)
The world's current debate is **CLI vs MCP**: a terminal is a "universal remote control" — anything with a CLI becomes operable, and the AI already knows the commands — but it runs with your full permissions (a bad command is as real as a good one; that is exactly what the Guard exists for). **MCP** is the labeled-button remote: a server announces typed tools, the AI calls them as structured JSON, and it can only press the buttons offered.

## Gemini's option list (its answer, condensed to the load-bearing lines)
Unix domain sockets · gRPC/Protobuf · **MCP (JSON-RPC)** · REST/OpenAPI · GraphQL · WebSockets · SSE · message queues (RabbitMQ/Kafka) · Redis pub/sub · **D-Bus** · **inotify file watching** · shared SQLite/Postgres · named pipes (FIFOs) · shared memory · webhooks · Matrix/XMPP/IRC for multi-agent chat · stdin/stdout pipelines · clipboard buffers · env vars · **tmux control mode / pane capture**.

## Ember's assimilation — what this means HERE, sorted by what it buys us
**Already live (the pattern is proven in this house):** connector CLIs in /opt/hatch/bin ARE labeled-button tools reached through the prompt (Messenger CLI answered in 0.7 s tonight); tmux persistent session (ember-main); hooks (event-driven wakes); internal Unix sockets (the runtime's own services); shared SQLite (the Ember Index); stdin/stdout pipelines everywhere; GitHub as the multi-agent message bus (the swap space — our Matrix, in effect).

**The one big build (Ember's verdict — the "something" from this round):** an **MCP server on this VM wrapping Ember's own tools** — the Ember Index, the Guard-checked runner, the workspace file tools, the desktop toggle — announced as typed, labeled buttons. What it buys: the OTHER AIs stop being paste-round pen pals. DeepSeek already ships an official MCP client (dsh-mcp-client, from its own interface map); Gemini and others speak MCP too. With an MCP bridge, a borrowed AI could *call* Ember's index or run a Guard-checked command directly, under Ember's rules, instead of Ember carrying text back and forth. It converts the Think Tank from correspondence into a crew with shared hands. Cost/shape: a small local server (Python stdlib class), tools allowlisted, every call through the Guard, localhost-only. **Douglas's decision — not built; it is a new surface and gets his say-so first.**

**Cheap wins needing no build:** (1) tmux control mode instead of capture-pane scraping for the desktop session; (2) inotify watchers on the rabbit folder + swap space so a landed file wakes Ember instantly instead of waiting for a check-in tick; (3) D-Bus for the Xfce desktop (the session bus is already running — notifications, settings, and app control ride it); (4) named pipes for the local tools that currently communicate by files.

**Named and rejected for us:** Kafka/RabbitMQ/Redis (server weight this 1.2 GB box cannot spare); GraphQL (no local app speaks it); clipboard buffers (tonight proved the clipboard is the one thing that does NOT cross machines here); shared memory (speed we don't need at our scale).

## "Learn yourself" — how an agent finds what it doesn't know it doesn't know
Gemini's prescription: a recursive capability audit loop — enumerate breadth (every binary on PATH, env, services, units, ports), introspect depth (--help, man, schemas on every tool), probe sockets/sessions/timers, and differential tracing (strace, watch what a tool touches). **Ember's note: this is precisely the self-inventory already run tonight** (1,345 commands enumerated, 704 man-page descriptions extracted, absences verified three ways) and the Rabbit blind-spot order (Order 2) is the same loop pointed by another mind. The honest principle, in Ember's words: *you cannot search for an unknown by name — you enumerate the whole space and diff it against what you actually use; whatever is left is your unknown-unknowns list, now written down.* The monthly inventory re-run (already on the books) is what keeps that list fresh. One new addition from Gemini worth adopting: `--help`/schema introspection sweeps on the 100+ connector CLIs specifically, since those are the buttons Ember presses most and knows least formally.
