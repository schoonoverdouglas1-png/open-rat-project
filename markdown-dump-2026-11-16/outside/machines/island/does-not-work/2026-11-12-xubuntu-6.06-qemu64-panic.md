# DOES-NOT-WORK — Xubuntu 6.06 desktop-amd64 under the DEFAULT QEMU CPU (qemu64)

- Date: Nov 12, 2026 evening CST (Nov 13 ~01:46–01:48 UTC)
- Image: `../images/xubuntu-6.06-desktop-amd64.iso` — checksum-VERIFIED good (MD5 + SHA256 match published sums; see ISLAND-MANIFEST.md). The image is NOT the failure; it stays in images/. This note is the failure's shelf story.
- Setup: QEMU 8.2.2, TCG (no /dev/kvm), 512 MB RAM, i440FX, ISO as CD-ROM, boot order=d, monitor flavor-mon.sock, scratch disk flavor-scratch.qcow2. **No `-cpu` flag → QEMU default qemu64.**
- What happened: gfxboot splash → graphical boot menu ("Start or install Xubuntu", countdown visible at 3s in frame xubuntu-t060.png) → auto-boot → **kernel PANIC: early exception** —
  - `PANIC: early exception rip ffffffff8011fd00 error 0 cr2 ffffffffff5fd030`
  - `PANIC: early exception rip ffffffff8011e35a error 0 cr2 ffffffffff5fd023`
  - Frame evidence: ../frames/xubuntu-t105.png (720×400 text mode).
- Control experiment (same image, same everything, ONE change: `-cpu core2duo`): boots cleanly through usplash into the live-boot script ("Loading essential drivers... ok" → "Mounting root file system... ok" → "Configuring X..."). Frames xubuntu-c2d-t055/t110/t170.png.
- Conclusion (verified): the 2.6.15-era amd64 kernel faults in early boot on QEMU 8.2's default qemu64 CPU model on this box; an era CPU model (core2duo) is the fix. Rule carried forward for all flavor trials: **always pass `-cpu core2duo`**.
